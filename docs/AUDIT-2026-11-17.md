`npm test` went from 850 checks to 860, all passing. Two of the new ones
replaced a hole in an old check:

- The contrast check was titled "passes WCAG AA on every surface" and graded
  three hex literals per theme. It reads ten surface tokens by name now, and
  fails when a theme grows a surface it does not name. That is how finding 1
  stayed green.

  message about "a dead src". Nothing checked the file existed. A new check
  reads the built pages and requires every local file they load.

Two things about fix 3 are judgment calls worth a second look:

- The forced-colors block uses `!important`. The mode forces whichever
  declaration wins the cascade, so a longer normal selector does not lose to
  the block. It wins, and is repainted to nothing. I measured that happening
  twice before adding the flag. It is the same reason the reduced-motion
  block in `base.css` carries it.
- Two palette scans in `tests/run.mjs` ("colour must come from a token") now
  skip the forced-colors blocks, because a token there paints nothing. A new
  check holds those blocks to system colours only, and I confirmed both old
  scans still fail on a stray colour outside the block.

## Found, not fixed

Ranked by what a user meets first. Each is measured unless it says otherwise.

### Accessibility

1. **Calendar days carry `aria-selected` on a `<button>`.** The runtime
   builds `<td role="gridcell"><button class="cm-cal__day" aria-selected>`.
   `aria-selected` is not allowed on a button (axe `aria-allowed-attr`,
   critical, 5 nodes). It belongs on the gridcell. The CSS, the runtime and
   the new forced-colors rules all key off the button, so this is a real
   change, not a rename.
2. **The header brand's name does not contain its visible text.**
   `Header.astro` renders `<a class="cm-header__brand" aria-label="Home">`
   around the site name. Someone using voice control says the name they can
   see and nothing answers (axe `label-content-name-mismatch`, serious, on
   all 10 pages; 27 nodes in total with the bell and the guild rail).
3. **Scroll containers cannot be reached from the keyboard.**
   `.cm-scrollarea`, `.cm-scroll-fade*` and `table.cm-prose-table` scroll
   but are not focusable and hold nothing that is (axe
   `scrollable-region-focusable`, serious, 16 nodes).
4. **`.cm-kv--link` is not a valid description list.** `Kv.astro` emits
   `dl > div > a > dt + dd`. A `dt` and `dd` have to be children of the `dl`
   or of a `div` in it (axe `definition-list` and `dlitem`, 14 nodes).
5. **The programme guide is a grid with no rows.** `.cm-guide` has
   `role="grid"` and children with `gridcell` and `rowheader`, with no
   `role="row"` between (axe `aria-required-children`, critical).
6. **18 touch targets are under 24 px** (WCAG 2.5.8) on a 390 px phone: 11
   data-table row checkboxes at 17 x 17 with no label, 5 `.cm-toast__close`
   at 16 x 44, 2 `.cm-chip__x` at 20 x 20. 36 are under the library's own
   44 px `--tap`: `.cm-bell` 32 x 32, `.cm-toolbar__view` 32 high,
   `.cm-sidebar__grouplabel` 32 high, the message actions at 29 to 36 wide.
7. **A selected table row is a 1.09:1 fill and nothing else** in the dark
   theme (`--bg-3` on `--bg`). Not a forced-colors problem; it is that faint
   in the normal theme.
8. Showcase markup only, not library output: two `<main>` on one page, a
   heading level skipped on 7 pages, spec rows with `role="listitem"` and no
   list, two unlabelled checkboxes in the tables section, and on `/testing/`
   a tab whose `aria-controls` names an id that is not on the page.

I did not triage every axe node one by one. The counts are axe's, across the
10 pages; the descriptions are the ones I opened.

### Dependencies

9. **`npm audit` reports 6 advisories in the dev toolchain** (1 moderate, 5
   high: astro, vite, zod, undici, sharp, source-map-js). Every astro that
   fixes them (7.4.7 and up) needs Node 22.23.4 or newer, and this host has
   22.23.2. `npm audit fix` moves the lock to astro 7.4.12 and the build
   then refuses to start here, so I left the lock alone. CI installs Node
   through `setup-node`; I did not check which 22.x it resolves to. What
   ships has no dependencies: `npm audit --omit=dev` is clean. Bump Node,
   then `npm audit fix`, then raise `engines.node` to match.

### Process

10. **CI runs the build and `tests/run.mjs`, and nothing else.** None of the
    hundred or so Playwright harnesses run there or from any script. They
    default to at least five different addresses (ports 4471, 4321, 8911,
    one LAN IP), and 146 files under `tests/` hold a `/root`, `/mnt/pve` or
    `/reiki` path. The repo is public. Every fix above that needed a browser
    was a defect `npm test` could not see.
11. **The fleet is behind.** `check-design-sync.sh` exits 1: the consumers
    are up to 347 lines of `components.css` and 161 lines of `cli-mono.js`
    behind `master`, before this branch. None of them has the fixes above
    until it is re-vendored.
12. **Rule 1 in `AGENTS.md` is not what the file does.** "No hex, px, or
    timing literals in `components.css`": it has 398 px literals (209 are
    1px hairlines), 17 timing literals, and 60 media queries over 17
    distinct breakpoints. Either the hairline and the breakpoints become
    tokens, or the rule says what it means.
13. Repo: 11 local branches hold nothing `master` lacks and sit 130 to 210
    commits behind it; `b26-chart` has diverged by 67 commits each way;
    `origin/main` from September sits beside the default `master`; the
    version is `0.1.0` and no tag is a version.
14. The site: no favicon (404), no 404 page, no sitemap, and the showcase
    does not use its own `<Head>` component, so it has no canonical link, no
    Open Graph tags and no `theme-color`.
15. Nine tokens are declared and never read: `--accent-glow`, `--cyan`,
    `--green`, `--shadow-1`, `--z-root`, `--sidebar-primary`,
    `--sidebar-primary-foreground`, `--sidebar-accent-foreground`,
    `--sidebar-ring`.

## Modernization

What the library already requires matters here. It uses `[popover]`,
`:has()` (11 rules) and `@property`, so it already needs a 2024 browser. The
items below do not raise that floor much, and each one says by how much.

| # | Change | What it buys | Cost and risk |
| --- | --- | --- | --- |
| A | `light-dark()` with `color-scheme` for the palette | Each colour is declared once. Today 36 tokens are written 4 or 5 times (two root themes, two scoped themes, print): 236 declarations for 109 tokens. Fix 1 above had to be made in three places. Nested scoped themes come free. | Needs Safari 17.5 (May 2024). On anything older every colour is lost, not degraded. Yours to decide. |
| B | Cascade layers: `@layer tokens, base, components` | A consumer's own CSS wins without a specificity fight. It also removes the Tailwind problem: unlayered CSS outranks every Tailwind layer, which is why `make-scoped-entry.mjs` exists. | Baseline since 2022. Every consumer must re-vendor at once, since layered and unlayered copies do not mix. |
| C | Ship a minified build beside the source | `components.css` is 487 KB, 63% of it comments; minified it is 168 KB, 28 KB gzipped. `cli-mono.js` is 300 KB raw, 105 KB minified. A flat install serves the raw files. | Adds a build step to the published artifact, which `AGENTS.md` forbids. A generated `dist/` checked by the sync script would keep the source as the truth. |
| D | Split `tests/run.mjs` | It is one 1.14 MB file with 860 checks. A failure is hard to find and two lanes cannot edit it without a conflict. | Mechanical, but every check moves. Do it between features. |
| E | An ES module entry and a `.d.ts` | Consumers import what they use and get types. The IIFE stays for flat installs. | The runtime is one closure with shared state, so real tree-shaking means splitting it. A typed wrapper over the global is the cheap half. |
| F | `AbortController` for teardown, and a `destroy()` | 147 listeners are added and 3 were ever removed. Fix 4 handles the long-lived ones; the rest die with their elements. A `destroy()` would let a SPA unmount cleanly. | Small now that `cmWhileConnected` is the one path for long-lived listeners. |
| G | CSS nesting | Shorter rules, state next to its block. | Baseline 2023. Pure churn in a 12k line file unless it rides along with another change. |
| H | `@starting-style`, anchor positioning, `field-sizing`, container queries | Entry animation without script; `anchorPopover` (144 lines) and the tooltip clamp (161 lines) shrink; textareas grow on their own; components respond to their container instead of 17 viewport breakpoints. | Anchor positioning is the newest of the four, so check Firefox before leaning on it. Adopt each behind `@supports` with today's script as the fallback. |
| I | Follow the OS theme by default | A first visit matches the reader's system. Today it is dark unless a choice was saved, and `prefers-color-scheme` appears nowhere. | A product decision. A test pins dark as the default on purpose. |

My order: the Node bump and item 10 (wire the browser harnesses into CI)
first, because every fix on this branch was invisible to CI. Then A and B
together in one fleet-wide re-vendor. C when someone needs it. The rest when
a feature touches the code anyway.
